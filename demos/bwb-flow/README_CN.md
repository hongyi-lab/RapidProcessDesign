# BWB 候选设计工作台 · review-v2

本轮入口在仓库的 **`demos/bwb-flow`**。它独立运行于 [本地界面 3981](http://127.0.0.1:3981/)，计算服务为 `127.0.0.1:8842`。旧应用的 3900 页面和在线站点仍保留，展示的是原平台；本轮 BWB 功能请从这里启动。

工作台提供两种明确区分的模式：**低阶工程模型的候选分析与有限优化**，以及**真实 MIT 外部模型的原生 CL/CD/LD 系数分析**。老师可以追溯每次候选、使用的模型/配置、燃油求解尝试、约束及对应工况。没有完整 CFD/FEA 整机验证，也没有把 MIT 缺失的配平和载荷能力补成“已接通”。

## 启动

需要 Python 3.11+、Node 22.13+。首次在本目录的 `ui` 中安装锁定依赖：

```sh
cd demos/bwb-flow/ui
npm ci
```

Windows：双击本目录的 [Start-Demo.cmd](Start-Demo.cmd)，结束时双击 [Stop-Demo.cmd](Stop-Demo.cmd)。启动脚本依次查找仓库虚拟环境、本机捆绑运行时和 PATH 中的 Python；可指定解释器：

```powershell
./Start-Demo.ps1 -PythonExecutable 'C:\Python312\python.exe'
```

其他系统或手动运行：在本目录执行 `python server.py`；另开终端进入 `ui`，执行 `npm run dev -- --hostname 127.0.0.1 --port 3981`。低阶计算与离线评估只用 Python 标准库。真实 MIT 推理另需 NumPy，以及下文说明的外部资源。

同一端口只运行一个独立 demo 副本。如果之前启动过仓库外的 BWBFlowDemo，应先用那个副本的停止脚本关闭，再启动这里的版本。`GET http://127.0.0.1:8842/health` 应返回 `version: review-v2`。本轮不部署在线站点，不接 agent，也不修改旧应用源代码。

## 推荐查看顺序

1. 进入“低阶工程模型 · 整条演示链”。左侧分开填写固定任务、候选硬件、载荷工况及模型/求解参数；“分析当前候选”生成新记录。额定载荷决定固定系统质量，本次装载只改变任务状态。
2. 在“分析与三维”查看外形、外翼梁盒和实际计算截面。旋转、缩放、切换视角；显示几何和计算共享站位、翼型厚度及梁盒布局。几何加权四分之一弦点是参考点，不是已识别的真实气动中心。
3. 分别查看模型能力、数值收敛、演示约束、独立证据四层状态。点开约束可追到实际值、限值、模块、工况、状态或载荷 hash；失败时保留局部有效结果及失败阶段。
4. 查看燃油扫描/括区记录；无效尝试不被当作正负残差。任务曲线按真实秒数绘制，残差按真实评价编号绘制。修改配置后，旧结果继续保留，重新运行才生成新配置下的记录。
5. 进入“固定任务优化”，冻结当前任务和模型，运行有边界的候选搜索。查看基线、网格对照、最佳已评价候选、搜索停止条件、最紧约束和碰到的变量边界；可回看每个评价的完整记录。
6. “实际流程”提供工程总览与固定候选的分析依赖；具体执行情况以模块记录为准。“模型与证据”展示本次真实配置和覆盖边界。条件不一致的基线不能给出同任务优劣排序。
7. 切换“MIT 资源 · 原生系数分析”，使用 MIT 的原生几何及高度/KCAS/攻角调用真实模型。该模式不将原生参数伪装成当前 demo 的三维外形或整机配平结果。

## 本轮实际执行链

`configuration.py` 的不可变 `ModelConfig`、`SolverConfig` 是计算参数来源；`GET /defaults` 返回对应 schema、单位、范围、模块方法及默认值。每次分析保存冻结配置、配置 hash、设计 hash、任务/工况身份与 `analysis_hash`，独立运行另有 `analysis_id`。代码与配置实现的内容 hash 也进入追溯信息。

| 环节 | 当前实现 | 结论边界 |
|---|---|---|
| 候选来源 M03 | 显式使用现有尺寸；分析与搜索都记录 `skipped / existing_geometry` | 尚无任务驱动的初步尺寸生成器，不把手填种子称为自动 sizing |
| 几何与硬件 M04/M09 | 三段梯形外形；贴合演示翼型的薄壁梁盒；部件质量与 EI 来自同一截面/布局 | 蒙皮与梁盒补强分层；简化梁仅使用梁盒 EI，不代表完整蒙皮承载、实体 CAD 或舱内装载检验 |
| 内层 M05/M06/M10 | ISA、低阶线性气动/配平；爬升/巡航/下降的中点积分；有效相邻燃油括区后二分并复核残差 | 稳定性、迎角/舵偏及功率保护保留；未找到括区是证据不足，不是全域无解证明 |
| 载荷与结构 M07/M08 | 椭圆升力与部件质量惯性卸载；实际中点集中力对象直接交给外翼梁，传递同一个 case/hash | 根部固支、仅外翼弯曲；无扭转、屈曲、中央舱、完整包线或 FE 压力场 |
| 约束与外层 M11/O01 | 有符号约束；网格对照和坐标模式搜索共用 `analyze()` | 在已评价且满足演示约束的候选中选取；不是全局最优证明 |
| 独立复核 M12 | 明确记录 `not_performed`，给出需要补充的独立证据 | 当前候选不能称为已验证飞机 |

燃油默认每航段 36 步、容量内扫描 101 点、残差容差 `1e-5 kg`；这些均可配置。硬件质量在内层固定，不以增厚“闭合应力”。曾漏解的 `tank_offset_mac=0.45` 已有回归测试，不通过删除静稳定或功率检查让它通过。

外形使用对称厚度函数 `h(u)=τ·c·4u(1−u)[1−0.5(2u−1)²]`，τ 为配置中的最大厚弦比，上下表面为 ±h/2；面积系数为 0.6。梁盒前后界为 0.20c/0.55c，截面沿该厚度曲线，薄壁线积分给出材料面积、质心和惯性矩；不再把前梁处的薄截面当成满高矩形。三维颜色与梁肋不是全机 FE 应力云图。

默认载荷工况是海平面 60 m/s、2.5g 的**持续恒速机动**，要求推进功率足够。显式 `instantaneous` 模式允许减速并记录对应动力学条件，不能把它解释为可以持续保持该速度。应力 120 MPa、挠度/外翼长 3%、载荷空间 0.12 m³等仍是待老师确认的演示阈值。

## 固定任务优化示例

默认固定本次装载 70 kg、巡航段 500 km、45 m/s、1500 m，目标降低起始质量。只改变翼展 `[7,10] m`、壁厚 `[0.8,1.6] mm`、额定功率 `[45,90] kW`；硬件的其余字段、任务、载荷和模型配置冻结。

先执行每变量 3 水平的 27 点网格，再从网格/合法基线中的优先候选进行坐标模式搜索。模式搜索另有 45 次新评价预算、最多 8 轮、初始步长为区间的 0.2、最小步长比例 0.015；确定性 `seed=0`，不依赖随机采样。缓存命中不会再收取计算次数。网格与模式搜索使用相同 evaluator，网格是低维对照，不能称独立物理复核。

本轮实际默认运行（`run_id=625c638fec23d8b2`）得到：

| 项目 | 结果 |
|---|---:|
| 基线起始质量 | 304.679072 kg |
| 网格中最佳满足演示约束的起始质量 | 254.170837 kg |
| 最佳已评价候选的起始质量 | 250.936341 kg |
| 最佳候选：翼展 / 壁厚 / 功率 | 7.0 m / 0.8 mm / 59.625 kW |
| 新评价次数 | 41 = 基线 1 + 网格 27 + 模式搜索 13 |
| 停止原因 | 步长小于搜索阈值 |
| 持续机动的功率余量 | 约 0.370596 kW |

翼展和壁厚碰到搜索下界；这说明候选受当前搜索范围与简化物理共同影响，不证明真实设计在边界处合理。额定装载这一固定约束恰好取等号，与随设计变化的机动功率约束分开报告；“活跃”标签只是归一化余量阈值，不是 KKT 证明。

有效但超限的候选保留真实目标与 `infeasible`；缺模型、超域或求解失败为 `unknown`，不给虚构的罚分目标。没有找到满足约束的候选时输出 `no_feasible_candidate`，不声称可行域为空。可选目标还有任务装油；可选 2–3 个连续变量仅限根弦、翼展、壁厚、功率。

复现与完整记录：

```sh
python optimization.py --output evidence/optimization-example.json
```

[默认优化记录](evidence/optimization-example.json)保存算法设置、每次候选、基线/最佳结果及独立复核状态。硬件或物理模型修改后，应重新运行该文件，不能沿用旧结果解释新版本。

## MIT 资源与 UQ

`model_adapter.py` 真实调用外部 MIT/nTop `predict_ld.py`。设置环境变量 `BWB_MIT_ROOT` 指向资源仓库根；未设置时检查本仓库旁的 `MIT/official_hackathon`。该目录需包含经核对的 `b516d4b3e2e5e34fbd5233eacdf15317a96dc2d9` 版本文件，运行解释器需有 NumPy。资源缺失或内容不符返回明确原因，不自动下载、复制权重或回退到假模型。

适配器检查原生几何键、decoder、原生几何盒、原始/转换飞行域、有限值和 CD>0。已实际运行示例得到 CL≈0.203178285、CD≈0.0166523163、LD≈12.20120257。能力仅覆盖系数；没有 Cm、舵效、分布载荷或结构响应。论文规范参考量虽然可查，wrapper 标签到参考面积的完整来源链仍未解决，运行时参考面积/长度/力矩原点为 null，不将 CL 直接乘以 demo 面积换成力。盒内也不等于联合训练分布有覆盖。

`uq_evaluate.py` 接受冻结的划分清单、独立参考数据及预测，检查 proper-train/validation/calibration/test 的样本与几何组隔离、完整预训练暴露身份、保护声明和单位/保真度。报告点误差；只有供应合法区间时才计算 coverage、width、interval score，并单列边界与优化所选候选。无独立数据保持 `not_evaluated`、`metrics=null`，不生成误差条。本轮未训练或校准模型，未实现 GRUBS；边际覆盖率不是特定飞机的安全概率。

```sh
python uq_evaluate.py --schema-example --output uq-template.json
python uq_evaluate.py --manifest split-manifest.json --reference reference.json --predictions predictions.json --output evaluation.json
```

模板只有空清单和字段说明，不是假造的真实数据集。完整能力契约、归一化来源与论文获取边界见[模型证据说明](docs/models-evidence.md)。

## 本地接口与检查

| 接口 | 返回 / 用途 |
|---|---|
| `GET /health` | 服务名、`review-v2` 版本 |
| `GET /defaults` | 输入、模型、求解配置的 schema 与默认值，模块元数据和优化默认设置 |
| `GET /models` | 低阶模型及 MIT 能力清单、MIT 原生示例与输入 schema |
| `POST /analyze` | `{inputs,model_config,solver_config}`；一次候选的真实执行记录 |
| `POST /optimize` | 同上加 `search`；固定任务下的网格与模式搜索 |
| `GET /analyses/{analysis_id}` | 本服务会话中缓存的分析，最多保留 250 条；完整导出应自行保存 |
| `POST /coefficients` | `{geometry_decoder_id,geometry,condition}`；返回 MIT `model` 和逐量可用性 `prediction` |
| `GET /uq/status` | 当前独立评估缺口；无数据时不返回虚假指标 |
| `POST /uq/evaluate` | `{manifest,reference,predictions}`；与离线评估 CLI 共用实现 |

```sh
python -m unittest -v test_engine test_core_v2 test_models_uq test_optimization
cd ui
npx tsc --noEmit
npm run build
```

模型/UQ 的 15 项测试与优化的 9 项测试已执行通过；其中合成案例只检查指标算术、隔离与搜索行为，实际 MIT 样例调用和小范围真实工程搜索另有明确测试。资源不可用时，真实 MIT 测试会注明跳过，不能算作模型已验证。核心回归覆盖燃油漏解、配置生效/冻结、几何截面、实际载荷接口及质量身份；完整运行证据由本轮验收记录汇总。

历史 [verification.json](verification.json)属于前一轮，不能当成本版的整机或浏览器验收。本轮45项后端检查、12项实际HTTP/数值检查以及浏览器关键路径检查已执行；详见 [本轮验收记录](evidence/verification-v2.json) 和 [图与界面验收说明](../../docs/evidence/bwb-round2/README.md)。1920px 窗口的原生截图存在工具裁剪限制，未将其标为完整截图验收通过。工程计算规格与两图入口见[工程说明](../../docs/bwb-engineering-pipeline.md)；可编辑图源位于仓库 `scripts/draw_bwb_engineering_pipeline.py`。
